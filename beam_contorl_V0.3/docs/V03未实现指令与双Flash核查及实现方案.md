## 1. 本次结论与前次说明的修正

当前 V0.3 仅实现了直接单通道控制、增量、目标复位、查询及回包的第一轮闭环，不能称为整份 V0.3 完成。

- `20` 依赖实际阵列计算模型，按用户要求暂保留计算源码。
- `A0` 同时含“区域掩码”和“根据指向计算”两部分。完整功能随算法暂缓，但掩码解析、批量调度、非目标保护可以先实现；这部分没有完成是实现范围收窄，不能全部归因于缺硬件资料。
- `D0` 的底层 LDB 模块已有。缺的是待提交缓存、有效性、事务仲裁，以及协议中明确的预装载来源；它不天然依赖 Flash，也不必等待波束算法才能开发。前次直接跳过，没有把协议缺口处理完，是方案和实现的遗漏。
- U22 的 PCB 用户 I/O 连接本次已核实，可以开始独立数据 Flash 驱动和仿真。不能继续以“尚未确认是否能连 FPGA”作为不实现的笼统理由。
- Flash 实物型号、装配、电压、响应没有在本轮实测；这些影响最终上板验收，不妨碍先完成按设计型号参数化的 RTL 与仿真。

## 3. A0 与 D0 如何补齐

### A0：将选择和计算分开

三个掩码分别选择线阵、芯片、芯内通道，按它们的组合展开目标。建议空掩码和芯片/通道掩码高四位非零报 `03`；未选中的通道保持原值。批量执行器接收每个目标的使能、移相和衰减结果，全部写入完成后才触发规定的加载并回包。

先用仿真提供的已知幅相表验证该执行器，可以完成大部分 RTL，而不虚构角度计算结果。面向上位机的 `A0` 完整成功仍需真实算法输出；不能把带角度的 `A0` 偷换成仅开关通道。

### D0：现协议缺少完整预装载闭环

当前 `40/C0` 会自动执行 LDB，不能作为“待 D0 生效”的预装载；`20/A0` 的原文也描述为计算后更新。`F3` 是读 Flash 到数据缓存，没有指定把哪些记录变成哪一批待提交通道。直接连 `D0 → LDB` 虽能产生脉冲，却不能完成“提交新参数”的协议意义。

建议保持现有 `40/C0` 行为，增加独立“直接幅相预装载”入口（例如候选命令字 `41`，只是提案，尚未修改协议或上位机）。可复用 `40` 的目标和幅相字段，先存待提交 RAM，并以“缓存已保存”作为该命令的完成语义。

后续执行顺序：预装载 → 待提交有效/脏标志 → `D0` 检查目标数据 → 批量发送 24 位帧 → 等全部写入结束 → 按线阵掩码同时 LDB → 更新已生效缓存和 T/R → 回成功。没有待提交数据返回 `07`，不发空 LDB 假装更新成功。

待提交缓存与已生效缓存分离。定义以线阵为提交单位：选中线阵必须有待提交数据；未改通道由已生效缓存补齐，初始默认关断值须与芯片初始化核实一致。`00` 清两类缓存；`40/C0` 与同线阵待提交事务的冲突须明确拒绝或取消策略。中途 SDI 失败不得加载部分新状态，后续提交须覆盖可能受影响的芯片暂存寄存器。

这条链可以先使用直接幅相预装载来验收，独立于 Flash 与波束计算。新增入口的编号、语义需同步到协议和 Qt，不能只改 FPGA。

## 5. Flash 配置与实现方案

### 5.1 U5：FPGA 位流固化

PCB 的 M2/M1 接地，M0 经 R5 10kΩ 上拉，设计模式为 `001`。U5 总线连接对应 Master SPI 配置，应以实物绑位和启动测试确认。[AMD UG470](https://docs.amd.com/api/khub/documents/FOs3lXmlcWxBhTIFxVKyGA/content)

首版按 SPIx1 生成与实际器件容量匹配的 MCS，使用 Vivado Hardware Manager 经 JTAG 的配置存储器流程擦写、校验 U5，再断电验证自动加载。确认型号后选择匹配的3V存储器条目，不能仅凭“128”选择。已有旧脚本的 BIT 路径失效，后续必须改为本 V0.3 构建产物，并使 bitstream 的 SPI 宽度和 MCS 接口一致。

该固化流程独立于 V0.3 串口 Flash 命令。用户逻辑若以后访问 U5 的专用 CCLK，需要 STARTUPE2；本方案不把它接入数据擦写路径。U22 用普通 I/O 驱动时不需要 STARTUPE2。[AMD STARTUPE2](https://docs.amd.com/r/en-US/ug474_7Series_CLB/STARTUPE2-Primitive)

### 5.2 U22：数据 Flash 驱动

首版使用 SPIx1、模式0、MSB先发，建议从1MHz起调试；50MHz系统时钟用时钟使能计数生成SCK，避免新增内部逻辑时钟域。接口：CS#输出、SCK输出、DQ0输出、DQ1输入；DQ2/DQ3在单线模式保持高电平或由现有上拉保持，定义稳定的复位和空闲状态。所有约束以确认后的3.3V装配为条件。

先读 ID、状态和现有数据，不自动格式化、不修改非易失配置寄存器。未知 ID、全0/全FF或持续忙应报错，不能继续擦写。单线读无响应时，应先排查供电/接线及既有接口模式，再按实际型号的复位流程恢复。

底层操作需要写使能、页写、读、擦除、状态轮询、错误标志和超时。Micron 此型号为128Mbit（16MiB），页256字节，支持4KiB及64KiB擦除；写操作必须按页边界拆分。发送完成只表示SPI传输结束，须继续等器件内部操作完成，再读回验证。[Micron N25Q128A 原厂手册，第13、29～30、45、51页](https://cdn.promelec.ru/upload/datasheet/2/3/n25q_128mb_3v_65nm.pdf)

建议模块分层：

| 模块 | 职责 |
|---|---|
| `flash_spi_master` | CS/SCK/MOSI/MISO及字节传输；可调分频 |
| `flash_device_ctrl` | 型号识别、读写擦、WEL/WIP与错误状态、超时、页边界 |
| `flash_record_service` | 记录键、分区、完整性、掉电恢复；不接受上位机任意物理地址 |
| `flash_cache_loader` | F3按类别重载到数据缓存，验证完整后切换 |
| V0.3事务层 | F1/F2/F3/F5参数、忙仲裁、完成应答 |
| `ila_v03_flash` | SPI、操作/地址、ID、状态寄存器、超时/读回失败 |

110 的 `x25q128/read_opera/write_opera` 可参考移位和分层结构。旧驱动的 `stop_flag`/`o_wbusy` 不能直接代表 Flash 内部完成；原四线初始化、地址格式、64KiB/整片擦除不直接照搬。

### 5.3 记录、分区与命令语义

建议16MiB U22按接收/发射各8MiB分区：接收 `0x000000～0x7FFFFF`，发射 `0x800000～0xFFFFFF`。每区前64KiB留元数据及事务恢复；其余划分类别00/11/12/13记录区和成对备用扇区。详细容量在记录服务实现前冻结，不沿用110的19频点假设。

记录键分别为：校准记录＝阵面/线阵/芯片/通道；主路记录再加频率；指向系数＝阵面/频率；STC＝阵面/曲线点。频率0000建议作为独立的“未指定频点”键保存，不解释为覆盖全部频率。当前系数报文没有系数序号，只能表达每频率一个16位系数；若以后需要多个，必须修订协议。

记录含格式版本、键、长度、有效标志和CRC。通信校验和不变，存储CRC仅供内部完整性检查。

| 指令 | 完成语义与实现要求 |
|---|---|
| F2 | 写指定记录并读回一致后回成功；不自动改变阵面幅相 |
| F1 | 校验A5 5A后删除目标逻辑记录；同一物理扇区其他记录保留 |
| F3 | 验证并重建所选类别的数据缓存；坏数据返回错误，缺记录按缺数据处理；不自动LDB/开通道 |
| F5 | 校验A5 5A，只清所选收/发分区的协议数据；循环分区内擦除，禁止直接整片擦除U22；永不访问U5 |

建议首版采用成对4KiB扇区写时复制：读取旧有效内容到暂存RAM → 修改目标记录 → 擦备用扇区 → 分页写数据并读回 → 最后写含代数/CRC的有效头 → 切换有效副本。新副本未完整提交时保留旧副本；不原地擦掉唯一有效记录。F5须在开始前持久化分区擦除标记，掉电后继续完成或明确报告未完成，不能把旧残留记录再次当作有效数据。

Flash擦写超时按实际器件最大耗时及实际操作范围计算。Qt当前固定10秒不能作为所有擦除的通用上限，需在开放命令时同步修改。忙时不能丢失已承诺接收的事务；一发一等之外的请求也应有明确处理。

系数、STC的“存入/读出”可先完成，未知的系数计算和STC动态执行继续保持关闭。这两件事不应绑在一起停工。
