# V0.3 待实现与遗漏功能清单（2026-10-28）

本文件只记录需求和核查结论。本轮不修改 RTL、XDC、上位机、协议或构建产物，不生成或烧写固化文件。“待实现”不等于板级硬件条件已经满足。

## 1. 当前基线

当前 V0.3 通过 J18 的 RS422 运行 115200/8N1 调试协议；`00/20/40/A0/C0/E0/F1/F2/F3/F5` 已有 RTL 路径。其中 `20/A0` 采用 110 的定点公式和暂定 `X_DIS=Y_DIS=167`、8×16 坐标，衰减码为 0；`F3` 只重建缓存，不把 Flash 数据应用于阵面。`D0` 和独立预装载已按用户先前决定删除，不列为遗漏。U22 是数据记录 Flash；U5 是 FPGA 配置 Flash。当前有 `.bit`，但未为本版形成已核验的 U5 固化交付链。以上状态依据本工程 `README.md`、`rtl/beam_ctrl_top.sv`、`rtl/beam_phase_calc.sv` 和 `docs/V03协议_按110对齐实施版.md`。

## 3. 翻查既有记录发现仍未闭合的项

| 编号 | 事项 | 当前状态与下一步 |
|---|---|
| G01 | **SDO 之外的硬件上板条件** | 最终版硬件审查仍列有 J21 JTAG 的 TMS/TDO 网络命名交叉、PUDC_B 配置期缺确定绑位、板载 50 MHz 时钟 V20 的非专用路由以及外部 I/O 时序未闭合。U4.U22 是 FPGA 的 PUDC_B 复用引脚，不能与数据 Flash 器件 U22 混淆；配置前需实物核查外部绑位。新功能不能用已生成 BIT 替代这些实板核查；JTAG 固化前尤其先核对功能脚与线束。 |
| G02 | **J18 后续同步输入的物理通路** | 既有硬件核查指出 `SYNC_CLK_TX1_P/N` 只到 J18.2/12，未追到 FPGA 接收链路。J18 RS422 的现有收发对可预留，但“把 RS422 留给同步”不等于同步时钟已经能进入 FPGA；同步信号、电平、边沿、编码和实际网络都需另立设计。 |
| G03 | **Flash 校准实际应用** | U22 `F2/F3` 已可仿真存取/重载，`20/A0` 尚未叠加 256 通道校准幅相/衰减；频率值到 0～31 频点索引的 Ku 波段映射、系数编号和物理缩放未定。还要定义 Flash 无记录/坏记录时的行为。 |
| G04 | **U22 实板与记录语义** | 原理图型号与实装华邦不一致，当前 U22 行为模型通过不能代替实板 JEDEC ID、写保护、页写/擦除、掉电恢复验证。现行 `F1` 擦整个 64 KiB 扇区，会清同扇区其他记录；`F5` 中断可能只擦除部分分区。这些是实际使用前需决定并验证的数据完整性问题。 |
| G05 | **未执行的协议字段** | `40` 的非零串/并口衰减、STC、窗函数、频率仍返回 `05`；`20` 的窗函数/STC/宽波束未执行；动态 STC、波束展宽/加权及对应系数表尚缺。按用户本轮决定，参考 110 的控制入口和计算流程，窗函数/STC/宽波束/脉冲形式上电默认均关闭；未实现的非零模式继续明确报不支持，不能静默当作已生效。 |
| G06 | **外部同步脉冲与门控** | 旧 110 外同步和部分收发交替模式仍返回 `05`。需同步来源、极性、周期、收发互锁保护间隔和异常后安全态。当前能执行的 110 `12` 模式源码实际为 25% 占空比，与旧文字的 10% 不同。 |
| G07 | **状态监测及保护** | 早期需求有温度、电流、锁定状态、故障/BIT 和健康监测；当前 `E0` 仅基础初始化、忙、错误和线阵使能。须先核实这些信号是否实际连 FPGA、由谁采集，再定义回包与保护动作。 |
| G08 | **真实 CID、MODE、通道映射** | 用户确认 CID 绑位已在 V0.2 验证。复查 V0.2 的 J1 实板记录：使用 `CHIP_CID_MAP=16'h3210` 时逻辑 chip0～3 各自开通都有可重复 RF 响应，支持这块线阵的四路功能寻址，故 V0.3 可继承该映射作为 J1 功能基线。原记录明确未测逻辑编号与实物 U1～U4、RF1～RF4 的逐点对应，也没有 ID0～ID3/MODE 引脚电压或电阻实装表；其他线阵和收发阵面的复用仍需一致性验证。详见 `V03阶段1板级基线核查_20261028.md`。 |
| G09 | **上位机调试体验与实板验收** | Qt 的 40/C0 跨阵面、跨线阵是依次发送多个单通道命令；20/A0 才有 FPGA 批量并行路径。迁移双 RS485 时应保持树形勾选，清楚显示任务数量、目标和失败位置；用实板验证通信、波形、幅相及应答，不把“模拟设备成功”当成硬件成功。 |

## 4. 实施前应冻结的输入与顺序

1. **先处理硬件事实**：实板已修改的 SDO 转换器方向及测量结果、MODE/CID 绑位、J21/J18 RS485 线束、JTAG 功能脚、U5/U22 丝印及 J18 同步网络；只有这些确认后，相关 RTL 才能设计成可验收功能。
2. **冻结阵元映射表**：给每个收/发阵面 128 个物理阵元列出二维坐标、线阵编号、SDI 编号、芯内 RF 口、相位符号。9.6 mm 作为已知间距写入表，分别核查 X/Y 方向和边界。DXF 是线阵板参考，整阵方向以架构图、实物和测试结果闭合。
3. **冻结芯片初始化表**：按用户已确认的 E 列提取；核对 0～127 以外寄存器、各幅相/衰减表、TX 使能默认、读写功能码、写入次序和芯片型号适用性。记录 E/F 冲突，不自行采用 F 列。
4. **再分模块实施**：双 RS485 接入及通信回归；初始化与状态；SDO 回读；几何/标定应用；U5 固化流程。每一项都需要仿真与实板证据，不能只看综合或应答成功。

## 5. 本轮芯片能力与硬件边界核查

| 项目 | 核查结论 | 本版处理口径 |
|---|---|---|
| PUDC_B | AMD 7 系列 FPGA 的配置期 I/O 弱上拉控制脚，低电平使能 SelectIO 弱上拉，高电平关闭；必须直接或经不大于 1 kΩ 电阻绑到 VCCO_14 或 GND，配置期不得悬空。最终版板级记录中 U4.U22 只与 U13.30 的 `FPGA_RX_SDI5_2` 相连，未见独立绑位。 | 核对实板电阻/电压和芯片配置启动行为，再决定硬件补绑方案；RTL/XDC 不能代替配置期电平。该 U4 球位与 Flash 器件 U22 是不同对象。 |
| `SYNC_CLK_TX1_P/N` | 最终版网络表核查显示分别只有 J18.2、J18.12 端点，未接 FPGA 接收引脚；用户观察属实。 | J18 RS422 对保留作后续同步输入不等于这对同步时钟已接通；若要求外部同步时钟，须补硬件接收链路并明确电平、终端、时序约束。 |
| TR 芯片直接能力 | `CCAR10405L数据手册V1.0.pdf` 与 `TandR_SPI_datasheet_CCARX01.pdf` 描述四路 RF 通道、收发切换/通道使能、各路收发移相与衰减码、控制寄存器/预置表、SPI 写入与下一帧 SDO 回读、片内温度相关 ADC 能力。移相标称 5.625° 步进，衰减标称 0.5 dB 步进。 | 先按 E 列完成寄存器初始化，再根据实测 CID/MODE 使能可靠读写；ADC 的具体寄存器和温度转换需按适用型号和实际回读复核。通用 SPI 文件的 16 位通道掩码不能理解成此颗四通道芯片有 16 个 RF 口。 |
| 窗函数 | 芯片没有“选择 Taylor/其他窗”的独立功能码；可接收上层算出的逐阵元幅度/衰减权值。 | 参考 110 权值路径，结合本阵列几何、标定和量化范围生成码表；默认关闭。 |
| STC | 芯片有衰减寄存器和外部触发/更新机制，但手册未给出自主按时间运行 STC 曲线的模式。 | FPGA/上位机负责时间基准、曲线和逐时隙更新；默认关闭。需测更新速率、收发时序和安全态。 |
| 宽波束 | 芯片可逐通道设置幅相及开关，没有“宽波束模式”或阵列波束计算器。 | FPGA/上位机计算对应阵元权值与通道掩码；默认关闭。 |
| 脉冲形式 | 芯片有 T/R 控制输入及收发切换能力，手册未定义 110 的脉冲形式编号、占空比或脉冲序列发生器。 | 脉冲时序/收发互锁由 FPGA 外部控制，默认关闭；借鉴 110 前须核对模式定义，尤其旧 `12` 模式 RTL 实际 25% 占空比、旧 `0xFF` 未实现。 |

上述“未见芯片内建模式”是依据现有两份手册的功能码、寄存器和时序说明作出的结论，不妨碍用芯片的幅相、衰减及 T/R 控制实现系统级功能。110 的结构可作参考，不能把旧阵列的权值、STC 曲线和脉冲比例原样当成本板参数。

## 6. 建议实施顺序（本轮跳过 SYNC_CLK_TX1_P/N）

1. **冻结可验证的板级基线**：拍照/测量实装 U5/U22 料号及 JEDEC ID；确认 SDO 实板改线、U13 的 DIR/OE 和每路回读电平；核查 PUDC_B 的配置期绑位及启动安全态、J21/J18 RS485 线束。继承 V0.2 在 J1 验证的 `16'h3210` 功能寻址，继续把逻辑编号与实物 U1～U4、RF1～RF4 和整阵坐标逐点对应，并在其他线阵复核相同绑位。此步可以与软件接口设计并行，但不可把 J1 功能验证扩大成整阵物理映射已验收。
2. **冻结协议和安全态**：逐命令定义目标选择、批量范围、应答与部分失败语义；确认芯片复位期间通道关闭、初始化失败不能开通道；窗函数、STC、宽波束和脉冲形式默认 0，尚未实现的非零值返回明确错误。不恢复已决定删除的独立预装载/D0 方案。
3. **迁移调试通信**：将协议 RX/TX 接到 J21 RS485 和 J18 备用 RS485，加入半双工方向、入口仲裁及应答回原入口；上位机改 USB-RS485 连接与端口状态，J18 RS422 不再承担本版调试协议。验证两口分别覆盖正常、错误、超时和并发命令，JTAG 仍可用。
4. **芯片初始化与 CID/SDO 闭环**：用 `Control_Reg` E 列生成带来源和校验值的初始化表，确认其余必要寄存器/幅相表及安全开关默认值；实现上电初始化状态机、失败关断。按真实 CID/MODE 改芯片寻址和读帧；接入 16 路 SDO，处理下一帧回读、目标匹配、超时/错误。先仿真，再用单芯片、整线、收发各 8 线实板读写验证。
5. **阵元几何与基础波束计算**：把已确认的 9.6 mm 间距与真实二维坐标/方向写成显式映射，核对相位符号；把 110 定点计算接入 20/A0，覆盖全部 128 通道和非目标保持。再接入 U22 校准缓存、频点映射与幅相/衰减码量化；用独立算例、已知角度和实板主瓣方向验收，不继续沿用 8×16/167 暂值作最终依据。
6. **110 高级控制逐项启用**：先完成窗函数的逐阵元权值与量化，再做宽波束权值/掩码，随后做 STC 曲线定时更新，最后做以 FPGA 内部时钟为基准的脉冲形式。每项独立定义命令含义、码表、默认关断、时序和保护，并与 110 源码逐项对照；未经实板验证不得显示为可用。需要 `SYNC_CLK_TX1_P/N` 或外同步输入的模式暂不实施。
7. **上位机统一目标交互**：保留阵面→线阵→芯片→RF口勾选树，让 00/40/C0/20/A0 等有目标的操作使用一致的可视化选择与目标预览；对只支持单目标帧的命令明确显示逐目标发送和逐项结果，对 20/A0 使用 FPGA 批量路径。无目标语义的 Flash/状态操作不展示无效勾选；不得要求用户手算编号。补齐初始化、SDO、模式、失败位置和任务进度显示。
8. **Flash 与交付验收**：U22 核实擦除边界、记录完整性、掉电恢复，并使 F3 校准缓存真正进入波束计算；U5 按实装 W25Q128JV 的准确后缀及工具支持生成/校验 SPIx1 固化文件。最后运行协议/RTL 仿真、AMD ROSS 辅助 RTL/约束检查、Vivado 构建与时序核查，做双 RS485、收发全线幅相、SDO、复位/断电重启和实际波束测量。每阶段保存构建版本、波形、命令日志及测量结果。

阶段 1 的 CID、MODE、U5 料号及 SDO 电气结果是相应实板验收门槛；在结果到位前，可以先开发并仿真可参数化的模块，但不能把假定值作为交付配置。同步时钟的板级改线、接收器和外同步协议留待单独硬件决策。

阶段 2 的协议目标、状态、默认关断及失败安全态已记录于 `V03阶段2协议与安全态冻结_20261028.md`；2024.2 仿真通过。忙时明确回 `04`、厂家初始化失败禁开通道等规则需要在后续阶段落地，当前不计作已实现。
