# V0.3 相对 BJN110 的设计差异待审清单

日期：2026-10-23。对照对象为原 110 调试串口协议及其 RTL，不把 110 的上游 `AA BB`、`CC DD` 报文混为同一协议。当前实现状态以本目录 RTL、Qt 上位机源码为准。此清单是审查材料，未据此修改协议、RTL 或上位机。

**已定结论：本项目不需要独立“预装载”命令。** 我此前建议的 `41` 命令及“D0 依赖预装载才能工作”撤回。`41` 从未写入 V0.3 正式协议、Qt 或 RTL；历史方案文档中仍有这项建议，不应继续作为实施任务。

## 一、已写入 V0.3 RTL 或 Qt 的差异

| 03 | 地址层级 | 110 校准帧使用 1 起始的子阵、芯片、通道编号，旧阵列规模和布线与本板不同 | 增加 `ARRAY`，线阵 `0～7`、SDI 线路索引 `0～3`、芯内通道 `0～3`；Qt、`40/C0/00` RTL 已采用 | 收发独立、各 128 通道、芯片和通道 0～3 是用户确定的适配；`ARRAY=02/FF` 以及相关限制由我补充。审查后两值是否需要。 |

| 11 | 精确识别命令及坏帧恢复 | 110 主要按命令高 4 位分类，半帧恢复不完整 | V0.3 按完整字节识别，带长度、校验、超时恢复；RTL 已实现 | 我提出的解析策略。通常建议保留，但不是 110 原行为。 |
| 12 | 尚未支持命令的回包 | 110 代码有自身命令路径，不使用 V0.3 状态码 | 当前 `20/A0/D0/F1/F2/F3/F5` 大多只检查格式，回 `05`，不执行功能；Qt 提供这些命令界面 | 我提出的渐进实现方式；不能将 Qt 有按钮理解为 FPGA 已支持。审查是否隐藏未实现入口。 |

## 审查边界

- 收发各 128 通道、收发分开的阵面、每线阵 4 路 SDI、芯片 24 位帧、功能位 TX=`001` / RX=`010`、128 时钟复位等，是用户决定和现板芯片资料要求；它们与 110 不同，但不属于我自行新增的协议功能。
- Qt 的自动校准仪器和扫描架接口留空，是用户要求的后续扩展，不属于当前 110 差异审查。
- 110 原协议文档有图表，源码可确认实际行为。本清单对“110 有命令入口”与“110 实际完成该命令”分别陈述；未把目录里出现的模块或状态名当成功能通过证明。
