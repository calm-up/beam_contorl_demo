# V0.3 U5 配置固化与冷启动操作记录

日期：2026-10-29。工具：Vivado 2024.2。FPGA：XC7A200T。配置存储器：板上 U5，128 Mbit SPI Flash。本文记录本轮已经完成的操作，并给出以后在 Vivado 中重复固化的步骤。U22 是协议数据 Flash，不是 FPGA 上电配置存储器。

## 3. 在 Vivado 2024.2 中固化 U5

### 3.1 烧录前核对

1. 确认板卡供电正常、JTAG 接到 J21 的**实际功能引脚**，Vivado 版本为 2024.2。J21 原理图 TMS/TDO 网络名存在交叉，按已经验证的实物线束或 `output/release_20261029/固化与测试说明.md` 中的实际针序接线。
2. 确认文件是本次目录下的 `beam_control_v03_spix1_explicit_16m.mcs`，目标是 **U5**。不要把 `.bit` 当成 U5 固化文件，也不要选 U22。
3. 核对 U5 的完整丝印和供电。此次 Vivado 读取的 JEDEC ID 为 `EF 40 18`，但该 ID 和工具识别名不能单独证明完整订货后缀。当前电脑的 Vivado 型号表含此前添加的 `w25q128bv-spi-x1_x2_x4` 条目；换电脑时不可假定该条目原生存在。

### 3.2 GUI 烧录步骤

1. 打开 **Flow Navigator → Hardware Manager → Open Target → Auto Connect**，在设备树确认 `xc7a200t_0`。如果显示 `Not programmed`，仍可通过 JTAG 间接烧录配置 Flash。
2. 右键 `xc7a200t_0`，选择 **Add Configuration Memory Device**。在型号列表搜索 `w25q128bv-spi-x1_x2_x4`，核对器件系列和容量，然后添加到 FPGA 下方。**本次实测**选择 `w25q128jv-spi-x1_x2_x4` 时，Vivado 报“选中 JV、检测到 BV”并在擦写前拒绝；若今后实装丝印与工具选型不符，应先查清实物型号和工具支持，不能仅凭容量替换型号。
3. Vivado 询问是否立即编程时选择 **Program Configuration Memory Device**。在文件栏选择 `output/spix1_explicit_20261029/beam_control_v03_spix1_explicit_16m.mcs`；地址范围使用文件中的地址。勾选 **Erase、Blank Check、Program、Verify**。
4. 开始后等待全部阶段结束。日志应出现 `Erase Operation successful`、`Blank Check Operation successful`、`Program/Verify Operation successful` 和 `Flash programming completed successfully`。**只有 Program/Verify 成功才算烧录完成。** 本轮第一次使用 BV 条目时擦除后报 `Invalid context`，因此重新执行烧录，第二次才成功；失败后不能假定 Flash 中仍有可启动镜像。
5. 保存日志、所用 MCS 路径、JEDEC ID 和型号选择。本次成功记录见 `output/spix1_explicit_20261029/program_u5_retry.log`。

### 3.3 烧录后可选的软启动检查

在 Hardware Manager Tcl Console 执行：

```tcl
boot_hw_device -timeout 60 [get_hw_devices xc7a200t_0]
refresh_hw_device [get_hw_devices xc7a200t_0]
```

本次软启动约 29 秒，DONE/EOS 均为 1，CRC/ID 错误位为 0。软启动证明 FPGA 能在这次触发后从 U5 读取并配置，**不等于断电上电的自动启动已经通过**。

## 4. 冷启动验收：避免 Vivado 轮询干扰

AMD UG908 说明：Master SPI 上电配置时，如果 JTAG 下载器连着 Hardware Manager，状态轮询和恢复操作可能打断配置。我们曾在保持 Hardware Manager 连接的条件下读到 `Not programmed`；同一份 U5 镜像随后通过 `boot_hw_device` 又能在 29 秒完成配置。因此按下面方式做独立冷启动验收：

1. **板卡先完全断电。**从板端拔下 JTAG 线，使 Hardware Manager 在上电配置期间无法轮询 FPGA。
2. 重新给板卡上电。**不执行 Program Device，也不执行 Boot from Configuration Memory Device。**等待至少 40 秒；如条件允许，可直接观察 DONE 引脚或板上功能。
3. 等配置期结束后再接回 JTAG，在 Hardware Manager 中打开目标并刷新 FPGA 状态；应显示 `Programmed`。再用既有上位机命令和阵面响应验证程序工作。
4. 记录是否为冷启动、等待时间、DONE 状态和功能测试结果。用户在本轮按此隔离方式复测后确认：**现在可以启动并工作**。这一结果由用户实板观察报告；本机日志另证实软启动 DONE/EOS 为 1。

如确需在 JTAG/Hardware Manager 始终连接时进行冷启动试验，可先在该 Vivado 会话的 **Hardware Manager Tcl Console** 执行 `set_param xicom.allow_cfgin_commands false`，再断电重启；该参数影响 JTAG 链上所有器件，且应在轮询开始前设置。最直接的独立冷启动验收仍是先断开 JTAG，等 FPGA 自行完成配置后再连接读取状态。

## 5. 结果判读与记录

| 现象 | 判读与下一步 |
| --- | --- |
| Program/Verify 失败 | 烧录没有完成；检查日志、JTAG 连接、U5 选型，不进行冷启动结论判断。 |
| Program/Verify 成功，20 秒软启动报超时 | 对本次约 9.7 MB、3 MHz x1 镜像而言等待不足；用 60 秒再次确认 DONE。 |
| 接着 Hardware Manager 冷上电后显示 `Not programmed`，断开 JTAG 冷启动成功 | 优先考虑 Hardware Manager 轮询干扰；不据此判定 U5 镜像损坏。 |
| 断开 JTAG、等待 40 秒后仍无法冷启动 | 记录 FPGA 的 DONE/INIT_B/PROGRAM_B、U5 的 CS#/CCLK/MISO 和电源上升时序，再查启动电气条件。U5.1 为 CS#，U5.6 为 CLK，U5.8 为 3.3 V。 |
