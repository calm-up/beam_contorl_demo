# V0.3 阶段 2：协议与安全态冻结（2026-10-28）

本文件以 `V03协议_按110对齐实施版.md`、当前 RTL 和用户已确认的决策为依据，作为后续双 RS485、芯片初始化、SDO 和上位机的共同接口约定。本阶段冻结语义并验证当前基线，不把后续尚未实现的功能写成已完成。`SYNC_CLK_TX1_P/N` 与依赖外同步的模式暂不纳入本版。

## 1. 帧、应答与状态

- 上行固定为 `AA DD 01 LEN CMD ARRAY PAYLOAD SUM 55`；`LEN=PAYLOAD字节数+8`，`SUM` 从版本 `01` 累加至载荷末字节取低 8 位。应答为 `AA DD 01 LEN 7F ARRAY 原CMD STATUS [附加字节] SUM 55`。迁移到两路 RS485 后帧内容不变，在哪个端口收到完整命令就从哪个端口回包。
- `00` 只表示该命令定义的动作已完成：写命令是 SPI/LDB 事务完成，`20/A0` 是其规定的批量事务完成，`E0` 是状态已成功读取。它**不表示 RF 波束已经测准**，也不表示配置到芯片内部的寄存器已由 SDO 校验。
- `03` 为参数、长度或目标范围错误；`04` 为暂不可执行（忙/初始化未就绪）；`05` 为该模式或命令尚未支持；`06` 为已发起事务的执行/校验失败。校验错误或不完整串口帧不进入命令执行；保持现有“丢弃、不回包”的帧层规则，并计入错误状态。
- 单条已受理命令最终只能产生一次应答。双 RS485 阶段每个入口至多一个未完成请求；不同入口并发时，执行器串行仲裁，未取得执行权的完整请求应明确返回 `04`，不能静默丢弃。长时间 `F5` 期间同样适用。当前分发器在非 IDLE 状态会忽略新 `frame_valid_i`，这是第 3 步必须修正的现状，不将其写成已实现。
- 上位机把跨多个单目标帧的任务显示为“逐目标发送”，保存每个目标的结果；一次 `00` 应答只对应一帧，不代表整批已完成。`20/A0` 是单帧内的 FPGA 阵面批量事务。

## 2. 命令目标与批量边界

| CMD | ARRAY 范围 | 目标/执行边界 | 成功应答条件 |
|---|---|---|---|
| `00` | `00` 收、`01` 发、`02` 双阵面 | 1 字节非零线阵掩码；目标线阵复位，未选线阵保持 | 目标复位序列和缓存清除完成；目标在复位期间门控关闭 |
| `40`、`C0` | `00` 或 `01` | 每帧仅一条线阵、一颗芯片、一个芯内通道；其余通道保持 | 目标使能与幅相两轮写入、LDB 完成，失败关断目标线阵门控 |
| `20` | `00` 或 `01` | 目标阵面全部 8 条线阵、每线 4 芯片×4 通道 | 整面计算与规定写入/LDB 流程完成；中途失败关断目标阵面门控 |
| `A0` | `00` 或 `01` | 线阵/芯片/通道三组掩码形成笛卡尔积；所选启用、其余禁用，覆盖目标阵面使能状态；零掩码可用作全关 | 同 `20` 的批量完成条件；零掩码不能被界面误显示成“未选择但保持原值” |
| `E0` | `00`、`01`、`02`、`FF` | 查询状态，不选择芯片通道 | 五字节状态返回完成；即使芯片尚未初始化也可查询 |
| `F1/F2/F3/F5` | `00` 或 `01` | 只操作所选阵面的 U22 数据分区；F1 为 64 KiB 扇区，F5 为该阵面 8 MiB 分区 | 记录服务完成且按既定校验通过；U5 配置 Flash 始终不在目标内 |
| `D0` 及未列命令 | 不新增 | 已删除的预装载/D0 语义不恢复 | 返回 `05`，无阵面副作用 |

`F1/F2` 记录内的芯片/通道字段是 Flash 地址/载荷字段，不表示实时操作阵面；`F3` 只重建缓存，不自动发送 SDI/LDB。上位机对这些命令不应展示会误导用户的阵元勾选目标。

## 3. 模式和默认状态

- FPGA 上电后接收、发射门控和脉冲模式寄存器均为 0；`pulse=00` 意味着 T/R 门控关闭。即使 `40/C0/20/A0` 写入了使能码，若请求仍为 `pulse=00`，成功应答也只说明配置事务完成，不说明 RF 通道已导通。上位机须区分“码值已写入”与“当前 T/R 已开通”。
- 现行 110 内部计数脉冲分支：发射 `01/11/21/31/41/51/61`，接收 `02/12`。只有用户显式选中非零模式才进入；无外同步输入所需的模式仍返回 `05`。旧 `12` 的源码占空比为 25%，不沿用旧文字的 10%。
- `40` 的串/并衰减、STC、窗函数、频率非零，及 `20` 的窗函数、STC、宽波束非零，当前均返回 `05` 且不发 SPI/LDB；按后续阶段逐功能开放。`A0` 当前仅有脉冲模式字段，不在协议中暗加窗函数/STC 字节。所有扩展默认关闭。
- 非零模式被拒绝时，不得悄悄回 `00` 或把原模式保留当成新模式执行；不会改变现有 T/R 门控或有效缓存。

## 4. 安全态和初始化语义

- 现有顶层在上电 POR 期间把 `RSTN` 拉低、`CSB/LDB` 置高、`CLK/SDI/T/R` 置低；分发器的门控和脉冲寄存器复位为 0。核心完成 128 个复位时钟及等待后，当前 `core_init` 置位。此处的 `core_init` **仅代表数字复位时序完成**，不代表厂家 E 列控制寄存器或收发幅相表已经写入并验证。
- 当前 `E0` 附加状态首字节 bit0 是上述复位时序完成标志。第 4 步接入厂家初始化时，须在不改变五字节长度的前提下把“复位已完成”和“芯片初始化已成功”区分开；建议首字节 bit1 表示芯片初始化完成、错误字节新增初始化失败位，具体位定义在实现前写入协议并同时更新上位机。不得把现有 bit0 直接对用户解释为完整芯片初始化。
- 第 4 步起，`40/C0/20/A0` 只有在目标阵面厂家初始化成功后才可触发射频；未完成返回 `04`，初始化失败返回 `06` 并保持 T/R 关闭。`00` 是故障恢复入口：目标复位后必须重跑目标初始化，不能仅复位 128 个时钟就恢复原有开通状态。
- 单目标写入失败时关断目标线阵门控；整面批量写入失败时关断目标阵面门控。批量中途可能已有部分芯片暂存寄存器被写入，下一次恢复须完整覆盖后再开通；不把失败事务标记为有效缓存。Flash 校验失败不改变阵面当前生效配置。
- 以上只约束 FPGA 配置**完成以后**的数字输出。配置期间的 `PUDC_B`、电平转换器 OE 和外部安全态属于第 1 步板级核查，不能由本段 RTL 规则代替。

## 5. 本阶段验证与剩余实现点
